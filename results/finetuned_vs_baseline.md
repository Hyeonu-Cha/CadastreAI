# Task 2.14 — fine-tuned BGE vs baseline (queries_all.jsonl, n=100)

## Headline

The fine-tuned `bge-au-housing-v1` checkpoint **regressed across every metric and persona** on the real eval set, despite scoring well on the synthetic dev split during training.

| metric    | baseline (`BAAI/bge-base-en-v1.5`) | fine-tuned (`models/bge-au-housing-v1`) | Δ      |
| --------- | ---------------------------------- | --------------------------------------- | ------ |
| Recall@5  | 0.383                              | 0.177                                   | −53.9% |
| Recall@10 | 0.450                              | 0.210                                   | −53.3% |
| MRR@10    | 0.352                              | 0.128                                   | −63.6% |
| nDCG@10   | 0.349                              | 0.146                                   | −58.2% |

Per-persona (R@10 / MRR@10):

| persona     |  n  | baseline   | fine-tuned |
| ----------- | --: | ---------- | ---------- |
| homebuyer   |  24 | 0.40 / 0.33 | 0.11 / 0.08 |
| investor    |  25 | 0.28 / 0.21 | 0.09 / 0.06 |
| researcher  |  51 | 0.56 / 0.44 | 0.31 / 0.18 |

## What the dev metrics said vs. what we got

Training (`RerankingEvaluator` on the held-out 10% of `triplets.jsonl`) showed:

| epoch | MAP    | MRR@10 | NDCG@10 |
| ----: | ------ | ------ | ------- |
|     1 | 0.7604 | 0.7627 | 0.8216  |
|     2 | 0.7833 | 0.7860 | 0.8389  |
|     3 | 0.7835 | 0.7863 | 0.8393  |

Strong on synthetic dev pairs, catastrophic on the real eval queries. Classic distribution mismatch.

## Failure mode

The FT model collapses toward AHURI-style passages regardless of query topic. Inspecting per-query results:

- *"How much stamp duty would I pay on an 800,000 dollar home in Victoria as a first home buyer?"*
  - **Baseline top-3**: `proptrack/.../victorias-stamp-duty-changes`, `proptrack/.../move-to-slash-stamp-duty`, `sqm-research/.../inside-business`
  - **Fine-tuned top-3**: `ahuri/.../changing-geography-of-homelessness`, `ahuri/.../filtering-as-a-source-of-low-income-housing`, `ahuri/.../demand-side-assistance-in-australias-rental-housing-market`

The fine-tuned model is no longer separating publishers/topics; it's pulled everything toward AHURI's research-paper register, which is the dominant source in the chunk corpus and therefore in the synthetic pair-generation pipeline.

## Likely root causes

1. **Pair-generation distribution skew** — `generate_pairs.py` samples (anchor, positive) from chunks. AHURI dwarfs the other publishers in chunk count, so the training set is overwhelmingly AHURI↔AHURI. The fine-tune learns "good answers look like AHURI."
2. **Synthetic anchor style ≠ real eval queries** — anchors generated by an LLM from passages tend to read like academic paraphrases of the passage, not like the natural-language eval queries (`"How does the First Home Owner Grant work in NSW and who qualifies?"`).
3. **Catastrophic forgetting of base BGE generality** — 3,943 pairs at lr=2e-5 for 3 epochs over a narrow distribution is enough to over-write the broad retrieval prior the base BGE encodes.

## What to try next

In rough cost order:

- **A. Stratified pair sampling** — cap per-publisher pair counts so AHURI doesn't dominate. Cheapest fix; addresses (1).
- **B. Anchor-style alignment** — bias the LLM prompt in `generate_pairs.py` toward natural questions (currently it appears to produce paraphrases). Addresses (2).
- **C. Lower learning rate / fewer epochs** — try lr=5e-6, 1 epoch. Addresses (3) at the cost of less learning.
- **D. Mix-in the existing eval queries** — augment training with the (query, gold_chunk) pairs from `queries_all.jsonl` (held-out a clean test split). Addresses (1)+(2)+(3) but risks evaluation-set contamination unless we split carefully.
- **E. Two-stage retrieval** — keep base BGE for first-stage retrieval, fine-tune a re-ranker on top (cross-encoder). Different architecture; likely the right long-term move.
